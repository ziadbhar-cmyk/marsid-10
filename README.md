# مرصد الأعمال — Marsad

منظومة ويب تجمع بيانات كل الأنشطة في مكان واحد وتحدّثها تلقائياً: أودو، والمنظومات المحلية (العلامة، أبو غريس، منظومة المصنع…)، وملفات Excel.

```
marsad/
├── server/          تطبيق الويب (FastAPI) — اللوحات، المشاريع، الربط، الـ API
├── agent/           وكيل المزامنة الذي يُركّب على جهاز المنظومة المحلية (ويندوز)
├── Dockerfile       لتشغيل السيرفر على أي استضافة
├── docker-compose.yml  للتشغيل على سيرفر دائم (Oracle مجاني) مع HTTPS تلقائي
└── render.yaml      للتشغيل على Render مجاناً
```

## كيف تعمل

| طريقة الربط | تُستخدم مع | كيف تُسحب البيانات |
|---|---|---|
| **أودو** | محل الأثاث | السيرفر يتصل بأودو مباشرة عبر XML-RPC كل 30 دقيقة (قراءة فقط). يسحب المبيعات (أوامر البيع + نقاط البيع) والمشتريات والمخزون وأرصدة العملاء والموردين والمصارف والمصروفات والإنتاج |
| **وكيل محلي** | العلامة، أبو غريس، منظومة المصنع | برنامج صغير على جهاز السيرفر المحلي يقرأ القاعدة (SQL Server / Access / MySQL / Firebird…) بمستخدم قراءة فقط ويرسل للسيرفر عبر HTTPS. الاستعلامات تُكتب وتُجرّب من الموقع مباشرة. لو انقطع الإنترنت يحفظ البيانات ويرسلها لاحقاً |
| **Excel / CSV** | أي منظومة كبداية أو حل احتياطي | رفع ملف مصدّر من المنظومة، مع مطابقة تلقائية للأعمدة العربية |

كل البيانات تتحول إلى نموذج موحد (مبيعات، مشتريات، مصروفات، خزينة، إنتاج، مخزون، أرصدة)، فاللوحات واحدة لكل الأنشطة، وفوقها لوحة موحدة تجمع الكل وملخص يومي على تيليجرام.

## التشغيل المجاني — اختر طريقاً واحداً

### الطريق (أ): Oracle Cloud Always Free (الأفضل: سيرفر دائم بدون نوم)
- مجاني دائماً: سيرفر ARM (حالياً 2 معالج و12 GB ذاكرة) + 200 GB تخزين.
- يحتاج بطاقة مصرفية دولية للتحقق عند التسجيل فقط، ولن يُخصم شيء طالما بقيت ضمن حدود Always Free.
- أحياناً تظهر رسالة Out of capacity عند إنشاء السيرفر. جرّب منطقة أخرى أو أعد المحاولة لاحقاً.

الخطوات:
1. أنشئ حساباً في cloud.oracle.com/free، ثم Create instance ← الصورة Ubuntu 22.04 ← الشكل VM.Standard.A1.Flex (2 OCPU، 12 GB).
2. في إعدادات الشبكة (Security List) افتح المنفذين 80 و443.
3. ادخل للسيرفر بـ SSH ونفّذ:
   ```bash
   sudo apt update && sudo apt install -y docker.io docker-compose-v2 git
   sudo iptables -I INPUT -p tcp --dport 80 -j ACCEPT && sudo iptables -I INPUT -p tcp --dport 443 -j ACCEPT
   # ارفع مجلد marsad للسيرفر (scp أو git) ثم:
   cd marsad && cp .env.example .env && nano .env      # غيّر كلمة المرور و SECRET_KEY و DOMAIN
   sudo docker compose up -d --build
   ```
4. الدومين: وجّه دوميناً (أو نطاقاً فرعياً مجانياً من duckdns.org) إلى IP السيرفر. Caddy يصدر شهادة HTTPS تلقائياً.
5. افتح `https://الدومين` وادخل.

قاعدة البيانات هنا ملف SQLite داخل `./data`، ويكفي بسهولة لملايين السجلات. للنسخ الاحتياطي انسخ مجلد `data` دورياً.

### الطريق (ب): Render + Supabase (بدون بطاقة وبدون إدارة سيرفر)
- **Render** (Free web service): ينام بعد 15 دقيقة بدون زيارات. هذا لا يؤثر عملياً، لأن الوكلاء يتصلون كل دقيقتين فيبقى صاحياً، وأول فتح بعد نوم يأخذ قرابة دقيقة.
- **Supabase** (Free Postgres): حجم القاعدة 500 MB، ويتوقف المشروع لو مر أسبوع بدون أي نشاط. الوكلاء يرسلون يومياً فلن يتوقف.
- الحجم يكفي لعدة سنوات من فواتير الأنشطة الأربعة على مستوى الفاتورة. لو كبر، احذف سطور التفاصيل القديمة أو انتقل للطريق (أ).

الخطوات:
1. Supabase: أنشئ مشروعاً، ثم Connect ← انسخ **Session pooler** connection string واستبدل كلمة المرور فيه.
2. ارفع مجلد marsad إلى مستودع GitHub خاص (Private).
3. Render: New ← Blueprint ← اختر المستودع (سيقرأ render.yaml). عبّئ:
   `DATABASE_URL` (من Supabase)، `ADMIN_PASSWORD`، و`PUBLIC_URL` (رابط الخدمة مثل `https://marsad.onrender.com`).
4. (احتياطي لسحب أودو) سجّل في cron-job.org مجاناً، وأضف مهمة كل 15 دقيقة على:
   `https://marsad.onrender.com/cron/tick?key=قيمة_CRON_KEY` (تجد القيمة في Environment في Render).

## أول استخدام

1. **مشروع جديد** ← البيانات الأساسية (الاسم، النشاط، المنظومة، الفروع، العملة، اللون).
2. **بيانات الربط**:
   - **أودو**: الرابط، اسم القاعدة، المستخدم، ومفتاح API. أنشئ مستخدماً للقراءة ومفتاح API من: التفضيلات ← الأمان ← مفاتيح API. اضغط "اختبار الاتصال" ثم "حفظ".
     ملاحظة: على Odoo Online (السحابة الرسمية) الوصول للـ API متاح حسب الخطة، وحسب علمي متاح فقط في خطة Custom. على Odoo.sh أو أودو مثبّت على سيرفر خاص يعمل بدون قيود.
   - **منظومة محلية**: اختر نوع القاعدة، نزّل حزمة الوكيل (الرابط والرمز السري معبّأين مسبقاً)، ثم اتبع `README_AGENT.txt` على جهاز المحل.
   - **Excel**: ارفع ملف التقرير وطابق الأعمدة.
3. **فتح البيانات**:
   - لمشاريع الوكيل: افتح **مستكشف الجداول** لترى كل جداول المنظومة وأعمدتها وعينات منها، ثم **ربط البيانات**.
   - في ربط البيانات اكتب استعلام SELECT لكل نوع، وسمِّ الأعمدة بالأسماء الموحدة (`date`, `doc_no`, `customer`, `amount`…).
   - جرّبه بزر "تجربة الاستعلام" (يُنفّذ على جهاز المحل خلال ثوانٍ وتظهر النتيجة)، ثم احفظ.
4. **الإعدادات** ← تيليجرام: ملخص يومي لكل الأنشطة على جوالك في الساعة التي تحددها.

### نصائح لاستعلامات المنظومات المحلية
- ابدأ بالمبيعات، ثم أرصدة العملاء والموردين، ثم المخزون، ثم الخزينة.
- `{since}` لعمود متابعة من نوع تاريخ (تاريخ آخر تعديل هو الأفضل)، و`{since_num}` لعمود رقم تسلسلي (ID).
- لو المنظومة ليس فيها تاريخ تعديل: استخدم تاريخ الفاتورة مع `>= {since}`. التكرار لا يضر، لأن كل سطر له معرف فريد (`line`) والمكرر يُستبدل.
- المرتجعات: أرسلها كمبيعات بقيمة سالبة، أو بـ UNION في نفس الاستعلام.
- المخزون والأرصدة "لقطة كاملة"، تُستبدل كل مرة.

## الأمان
- الدخول للموقع بكلمة مرور (غيّرها في `.env` / Render). استخدم HTTPS دائماً.
- الوكيل لا يفتح أي منفذ على جهاز المحل، ويرفض أي أمر غير SELECT. استخدم مستخدم قاعدة بيانات للقراءة فقط.
- كل مشروع له رمز سري مستقل للوكيل، وتقدر تغيّره من صفحة الوكيل.
- كلمات مرور أودو محفوظة في قاعدة السيرفر، فاستخدم مفتاح API لمستخدم قراءة وليس حساب المدير.
- خذ موافقة مالك كل نشاط، وراجع عقد مزود كل منظومة بخصوص القراءة من قاعدتها.
